# Frontend Architecture: SIH Hospital Management

This document outlines the architectural decisions, folder structures, and data flows specific to the React frontend of the MediFlow application.

## 1. Core Principles

The frontend is designed with **Domain-Driven Modularity**. Instead of globally grouping files by their technical type (e.g., all components in `/components`, all API calls in `/api`), the application is grouped by **business domain** (e.g., `/modules/patient`, `/modules/doctor`). This ensures scalability as the application grows.

## 2. Technology Stack

*   **Core:** React 18 (Hooks-based functional components)
*   **Build Tool:** Vite (For sub-second hot module replacement and optimized ESBuild bundling)
*   **Language:** TypeScript (Strict mode enabled for maximum type safety)
*   **Routing:** React Router DOM v6
*   **Styling:** Tailwind CSS v4 (Utility-first framework for rapid, responsive UI development)
*   **HTTP Client:** Axios (With global interceptors for JWT injection)
*   **Icons:** Lucide React

## 3. Directory Structure

```text
frontend/
├── src/
│   ├── api/                # Global Axios configuration and base API calls
│   ├── components/         # Global shared UI components (Button, Modal, Layout, Sidebar)
│   ├── context/            # React Contexts (AuthContext for global state)
│   ├── types/              # Global TypeScript interfaces
│   ├── utils/              # Helper functions (date formatting, role checkers)
│   └── modules/            # Domain-driven feature modules
│       ├── admin/          # Admin dashboard & staff management
│       ├── appointments/   # Appointment booking wizard
│       ├── auth/           # Login & Registration flows
│       ├── consultation/   # Doctor's live consultation interface
│       ├── doctor/         # Doctor dashboards & live queue
│       ├── patient/        # Patient dashboards
│       ├── preconsultation/# AI Chat and Audio recording UI
│       └── receptionist/   # Walk-in and manual queue management
```

## 4. State Management & Data Fetching

### 4.1 Global State (Authentication)
We use a lightweight **React Context (`AuthContext`)** to manage the global authentication state. It tracks:
*   `user` (ID, Name, Mobile, Role)
*   `token` (JWT)
*   `isAuthenticated` boolean status

### 4.2 API Layer
Instead of scattering `fetch()` calls inside components, we use isolated API services.
*   **`axiosInstance`:** A configured Axios instance in `src/api/axios.ts`.
*   **Interceptors:** Automatically attaches the `Authorization: Bearer <token>` header to every outgoing request. If a 401 Unauthorized is detected, it forces a user logout.

## 5. Routing & Role-Based Access Control (RBAC)

Routing is handled in `App.tsx` using a strictly protected layout wrapper.

### 5.1 The `ProtectedRoute` Component
Every domain route is wrapped in a `<ProtectedRoute allowedRoles={['ROLE_DOCTOR']} />`. 
*   If a user is not logged in, they are redirected to `/login`.
*   If a user is logged in but lacks the correct role, they are redirected to a fallback `/unauthorized` or their native dashboard.

### 5.2 Dynamic Sidebar
The `Sidebar.tsx` component reads the user's role from the `AuthContext` and dynamically renders the correct navigation links. A doctor will never see the patient booking links, and a patient will never see the doctor queue.

## 6. AI Integration Workflows (Frontend Side)

### 6.1 Pre-Consultation Chat & Voice
*   **Component:** `PreConsultation.tsx`
*   **Flow:** 
    1. Uses the browser's native `MediaRecorder` API to capture microphone input.
    2. Packages the audio blobs into a `FormData` object.
    3. Sends via `POST /api/patient/appointments/{id}/preconsultation/audio`.
    4. Renders the AI's response in a chat-like UI using standard flexbox message bubbles.

### 6.2 Clinical Summaries
*   **Component:** Doctor's `PreConsultationSummaryModal`
*   **Flow:** Fetches the AI-structured medical data (generated by the backend Python microservice) and renders it using clean Tailwind typography for rapid doctor consumption.

## 7. Performance Optimizations

*   **Vite Splitting:** Routes can be lazy-loaded in the future if the bundle size grows.
*   **No Mock Data:** The frontend strictly relies on backend state, preventing stale client-side hardcoded arrays.
*   **Tailwind JIT:** Only the CSS classes actually used in the `.tsx` files are compiled into the final CSS bundle, resulting in a microscopic stylesheet.
