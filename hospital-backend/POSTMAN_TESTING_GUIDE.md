# Postman Testing Guide

This guide provides step-by-step instructions to test the entire AI-Powered Hospital Backend workflow using Postman.

Because the system relies on role-based authentication and sequential workflows (e.g., Token -> Appointment -> Pre-Consultation), it is highly recommended to follow these steps in order.

---

## 1. Environment Setup

Before testing, set up a collection variable in Postman to store the JWT token automatically:
1. Create a new Collection named **Hospital API**.
2. Add a variable named `jwt_token`.
3. Set your Base URL (e.g., `http://localhost:8080`).

> **Note on Demo Mode:** When `DEMO_MODE=true` in `application.properties`, you don't need real Gemini API keys.

---

## 2. Authentication Flow

### Step 2.1: Register Patient (If new)
- **Method:** `POST`
- **URL:** `http://localhost:8080/api/auth/patient/register`
- **Headers:** `Content-Type: application/json`
- **Body (raw JSON):**
  ```json
  {
    "mobile": "9999999999",
    "password": "patient123",
    "fullName": "John Doe"
  }
  ```
- **Expected Outcome:** `200 OK` with message "Registration successful".

### Step 2.2: Login & Get Token
- **Method:** `POST`
- **URL:** `http://localhost:8080/api/auth/login`
- **Headers:** `Content-Type: application/json`
- **Body (raw JSON):**
  ```json
  {
    "mobile": "9999999999",
    "password": "patient123"
  }
  ```
- **Expected Outcome:** `200 OK`. The response contains your JWT `token` and `patientId`.
- **Postman Action:** Copy the `token` from the response and set it as your Bearer Token for all subsequent API requests.

---

## 3. Patient Workflow

*Ensure Authorization is set to **Bearer Token** using the token from Step 2.2.*

### Step 3.1: Book an Appointment
- **Method:** `POST`
- **URL:** `http://localhost:8080/api/appointments`
- **Headers:** `Content-Type: application/json`, `Authorization: Bearer <token>`
- **Body (raw JSON):**
  ```json
  {
    "hospitalId": "HSP-001",
    "departmentId": "DEPT-CARD",
    "doctorId": "DOC-001",
    "appointmentDate": "2026-08-26",
    "slotStart": "10:00:00",
    "slotEnd": "10:30:00",
    "appointmentType": "ONLINE",
    "reason": "Routine Checkup"
  }
  ```
- **Expected Outcome:** Returns the `appointmentId` and uniquely generated `tokenId`. 
- **Important:** Save the `appointmentId` for the next steps!

### Step 3.2: Start Pre-Consultation
- **Method:** `POST`
- **URL:** `http://localhost:8080/api/pre-consultations`
- **Headers:** `Content-Type: application/json`, `Authorization: Bearer <token>`
- **Body (raw JSON):**
  ```json
  {
    "appointmentId": "<PASTE_APPOINTMENT_ID_HERE>",
    "initialComplaint": "I have been feeling dizzy."
  }
  ```
- **Expected Outcome:** Returns the `preConsultationId`.

### Step 3.3: Upload Audio Complaint (Voice to Text)
- **Method:** `POST`
- **URL:** `http://localhost:8080/api/pre-consultations/<PASTE_APPOINTMENT_ID_HERE>/audio`
- **Headers:** `Authorization: Bearer <token>` (Do NOT set Content-Type manually, let Postman set it to multipart/form-data)
- **Body (form-data):**
  - Key: `audio` (Change type from Text to **File**)
  - Value: Select any dummy `.mp3` or `.wav` file from your computer.
- **Expected Outcome:** The backend will process the audio via Gemini Speech-to-Text and return a follow-up question generated by Gemini AI.

### Step 3.4: Complete Pre-Consultation (Generate AI Summary)
- **Method:** `POST`
- **URL:** `http://localhost:8080/api/pre-consultations/<PASTE_APPOINTMENT_ID_HERE>/complete`
- **Headers:** `Authorization: Bearer <token>`
- **Expected Outcome:** The AI generates a structured clinical summary attached to the appointment.

## 4. Doctor Workflow

*Note: For the Doctor workflow, you need a Doctor's JWT token. You can simulate this by changing the mobile number of `DOC-001` (from the DataSeeder) in the database to a number you can login with, OR just test the queue fetching by generating a token for the seeded doctor mobile (`9876543210`)*.

### Step 4.1: Doctor Login
- **Method:** `POST`
- **URL:** `http://localhost:8080/api/auth/login` (Using unified auth)
- **Body:**
  ```json
  {
    "mobile": "9876543210",
    "password": "doctor1"
  }
  ```
- **Action:** Copy the Doctor's JWT token.

### Step 4.2: Get Today's Queue
- **Method:** `GET`
- **URL:** `http://localhost:8080/api/doctor/queue/today`
- **Headers:** `Authorization: Bearer <DOCTOR_TOKEN>`
- **Expected Outcome:** Returns a list of `QueueToken` objects. The doctor can see the Token IDs and mapped Appointment IDs.

### Step 4.3: Save Consultation Notes
- **Method:** `POST`
- **URL:** `http://localhost:8080/api/doctor/consultations`
- **Headers:** `Content-Type: application/json`, `Authorization: Bearer <DOCTOR_TOKEN>`
- **Body:**
  ```json
  {
    "appointmentId": "<PASTE_APPOINTMENT_ID_HERE>",
    "observations": "Patient looks pale. BP is normal.",
    "assessment": "Mild dehydration.",
    "diagnosis": "Vertigo / Dehydration",
    "treatmentPlan": "Drink fluids, rest.",
    "doctorNotes": "Follow up in 1 week if symptoms persist."
  }
  ```
- **Expected Outcome:** Returns the newly created `consultationId`. Save this for the prescription.

### Step 4.4: Issue Prescription
- **Method:** `POST`
- **URL:** `http://localhost:8080/api/doctor/prescriptions`
- **Headers:** `Content-Type: application/json`, `Authorization: Bearer <DOCTOR_TOKEN>`
- **Body:**
  ```json
  {
    "consultationId": "<PASTE_CONSULTATION_ID_HERE>",
    "generalInstructions": "Take after meals.",
    "medicines": [
      {
        "name": "Paracetamol 500mg",
        "dosage": "1 tablet",
        "frequency": "Twice a day",
        "duration": "3 days",
        "instructions": "Take for fever"
      }
    ]
  }
  ```
- **Expected Outcome:** Returns the finalized `Prescription` object.

---

## 5. Troubleshooting Tips

1. **403 Forbidden:** You forgot to pass the `Authorization: Bearer <token>` header, or the token expired.
2. **400 Bad Request (Validation):** Ensure your JSON body strictly matches the field names and date/time formats (`yyyy-MM-dd` and `HH:mm:ss`).
3. **Audio Upload Fails:** Make sure you are using `form-data` in Postman and that the key is named exactly `audio`.
